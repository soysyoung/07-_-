# Multi Agent 실행 로그 EDA 보고서

## 1. 질문과 출처
<!-- 원본 양식: &#91;작성&#93; 어떤 역할이 느리며 어느 지표의 관측이 부족한가? 수업용 합성 데이터이며 실제 성능/가격 아님을 명시. -->

분석 질문은 `planner`, `researcher`, `writer` 중 어떤 역할의 실행 시간이 상대적으로 길고, 실행 시간·토큰·날짜 중 어떤 지표의 관측이 부족한지 확인하는 것이다. 입력은 `data/agent_runs.csv`의 수업용 합성 데이터이며 실제 서비스의 성능이나 가격을 나타내지 않는다.

## 2. 정제 정책
<!-- 원본 양식: &#91;작성&#93; 완전 중복과 ID 충돌을 구분. 실패 행/숫자 결측/날짜 미상 정책. 원본 보존 방법. -->

원본 CSV는 직접 수정하지 않고 읽기 전용 입력으로 사용했다. 모든 열이 같은 완전 중복 1행은 제거했지만, 같은 `run_id`에 서로 다른 내용이 있는 ID 충돌은 임의 선택하지 않고 오류로 중단하도록 했다. 에이전트 이름은 앞뒤 공백을 제거하고 소문자로 통일했다. 숫자로 변환할 수 없는 실행 시간과 토큰, 무한대 값은 결측으로 처리했고 잘못된 날짜도 날짜 미상으로 유지했다. 실패 행은 실행 횟수와 성공률의 분모에 포함했으며, 실행 시간 평균과 중앙값은 유효한 측정값만 사용했다. 결측값을 0으로 대체하지 않았다.

## 4. 한계와 개선안
<!-- 원본 양식: &#91;작성&#93; 1개 이상의 한계와 이를 확인할 추가 데이터/실험. 관계를 인과로 단정하지 않는다. -->

전체 정제 데이터가 12건이고 역할별 실행이 4건에 불과해 역할 간 차이를 일반화하기 어렵다. 실행 시간은 12건 중 9건만 측정되었고, `R08`, `R09`, `R10`의 실행 시간과 `R11`의 날짜가 결측이다. 또한 작업 난이도, 입력 크기, 실행 환경이 기록되지 않아 역할과 지연 시간의 관계를 인과로 해석할 수 없다. 개선하려면 역할별로 같은 작업을 여러 번 무작위 순서로 실행하고, 입력 크기·환경·오류 유형·재시도 여부를 함께 수집한 뒤 표본 수와 결측 원인을 확인해야 한다.

## 5. 재현 및 개인 기여
<!-- 원본 양식: &#91;작성&#93; 실행 명령, 실제 환경, 실제 테스트 결과, 수행한 수정, 담당 역할. -->

Windows PowerShell에서 프로젝트의 Python 3.13 가상환경을 사용했다.

```powershell
.\.venv\Scripts\python.exe .\main.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

`main.py` 실행 결과는 원본 13행, 정제 12행, 요약 3행, 유효 실행 시간 9건, 차트 2개였고 저장 후 재읽기 검증도 성공했다. 단위 테스트는 정상 입력, 실행 시간 전체 결측, ID 충돌 시 기존 출력 보존, 빈 입력 거부의 4개가 모두 통과했다. 이번 작업에서는 실습 08의 `validate_tables()` 통계 재계산 부분을 구현하고, 생성된 결과를 근거로 이 보고서와 테스트 기록을 작성했다.
