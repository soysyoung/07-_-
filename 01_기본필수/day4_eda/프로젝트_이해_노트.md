# EDA 프로젝트 이해 노트

## 1. 이 프로젝트를 한 문장으로 설명하면

여러 AI 에이전트의 실행 기록을 정리하고, 각 에이전트의 실행 속도와 성공률을 비교하는 데이터 분석 실습이다.

이 프로젝트에서 가장 중요한 것은 새로운 분석 기법을 만드는 것이 아니라, 이미 준비된 함수들을 연결하여 다음과 같은 하나의 분석 파이프라인을 완성하는 것이다.

```text
원본 데이터 읽기
→ 데이터 정제
→ 에이전트별 통계 계산
→ 결과 저장
→ 저장 결과 검증
→ 그래프 생성
```

## 2. 어떤 데이터인가?

기본 분석 데이터는 `data/agent_runs.csv`이다. 실제 서비스에서 수집한 데이터가 아니라 수업을 위해 만든 합성 데이터다.

원본에는 총 13개의 실행 기록이 있으며, 다음 3가지 AI 에이전트가 등장한다.

- `planner`: 작업 계획을 세우는 역할
- `researcher`: 필요한 정보를 조사하는 역할
- `writer`: 결과를 글로 작성하는 역할

CSV의 각 열은 다음 의미를 가진다.

| 열 이름 | 의미 | 예시 |
|---|---|---|
| `run_id` | 각 실행을 구분하는 ID | `R01` |
| `agent` | 실행을 담당한 에이전트 | `planner` |
| `latency_ms` | 작업 완료까지 걸린 시간(밀리초) | `100` |
| `tokens` | 실행에 사용된 토큰 수 | `50` |
| `status` | 실행 성공 또는 실패 여부 | `ok`, `error` |
| `day` | 실행한 날짜 | `2026-10-21` |

`data/agents_meta.json`에는 각 에이전트의 가상 토큰 단가가 들어 있다. 이 파일은 기본필수 단계보다 높은 응용 단계에서 실행 기록과 결합할 때 사용한다. 단가는 실제 가격이 아니다.

## 3. 무엇을 해결하려는가?

원본 데이터에는 현실에서 자주 볼 수 있는 데이터 문제가 일부러 들어 있다.

- 완전히 같은 실행 기록이 중복되어 있다.
- `Planner`, `RESEARCHER`, ` Planner `처럼 대소문자와 공백이 일정하지 않다.
- 실행시간이나 토큰 수 자리에 `bad`라는 잘못된 값이 있다.
- 실행시간이 비어 있는 행이 있다.
- 실행시간이 음수인 행이 있다.
- 날짜 자리에 `invalid`라는 잘못된 값이 있다.

따라서 원본을 바로 평균 내면 정확한 결과를 얻기 어렵다. 먼저 데이터를 정제한 후 다음 질문에 답하는 것이 이 프로젝트의 목적이다.

> planner, researcher, writer 중 어떤 역할이 상대적으로 느린가?  
> 각 역할의 성공률은 얼마인가?  
> 실행시간을 측정할 수 없는 기록은 얼마나 있는가?

## 4. 데이터 정제 방식

프로젝트가 적용해야 하는 주요 정제 규칙은 다음과 같다.

- 에이전트 이름의 앞뒤 공백을 제거한다.
- 에이전트 이름을 소문자로 통일한다.
- 완전히 동일한 중복 행은 하나만 남긴다.
- 숫자로 바꿀 수 없는 실행시간과 토큰 수는 결측값으로 처리한다.
- 음수나 무한대 같은 유효하지 않은 측정값도 결측값으로 처리한다.
- 잘못된 날짜는 알 수 없는 날짜로 처리한다.
- 실패한 실행도 실행 횟수와 성공률을 계산할 때는 포함한다.
- 실행시간이 없는 행은 평균 실행시간 계산에서 제외한다.
- 원본 CSV 파일은 직접 변경하지 않는다.

중요한 점은 결측값을 임의로 `0`으로 바꾸지 않는 것이다. 실행시간이 없다는 것은 실행시간이 0ms라는 뜻이 아니기 때문이다.

## 5. 프로그램의 전체 처리 흐름

### 1단계: 원본 읽기

`read_raw()`가 `agent_runs.csv`를 읽는다.

### 2단계: 데이터 정제

`clean_runs()`가 에이전트 이름, 숫자 값, 날짜, 중복 행 등을 정리한다.

### 3단계: 통계 계산

`aggregate_runs()`가 에이전트별로 다음 값을 계산한다.

- 전체 실행 횟수
- 실행시간이 정상적으로 측정된 횟수
- 평균 실행시간
- 중앙값 실행시간
- 성공률

`quality_report()`는 결측값 등 데이터 품질 정보를 계산한다.

### 4단계: 결과 저장

`save_tables()`가 정제 데이터와 요약 데이터를 CSV와 JSON으로 저장한다.

### 5단계: 저장 결과 재검증

`read_back()`이 방금 저장한 파일을 다시 읽고, `verify_roundtrip()`이 저장 전후 데이터가 같은지 확인한다.

이 과정을 왕복 검증(round-trip verification)이라고 이해하면 된다.

### 6단계: 그래프 생성

`plot_bar()`는 에이전트별 평균 실행시간 막대그래프를 만든다.

`plot_hist()`는 전체 실행시간의 분포를 보여주는 히스토그램을 만든다.

### 7단계: 최종 결과 반영

모든 계산, 저장, 검증, 그래프 생성이 성공했을 때만 임시 결과를 최종 `out` 폴더에 반영한다. 중간에 오류가 생기면 기존 결과를 보호한다.

## 6. 정상 완료 기준

기본 데이터를 정상적으로 처리하면 다음 결과가 나와야 한다.

| 항목 | 기대 결과 |
|---|---:|
| 원본 행 수 | 13행 |
| 정제 후 행 수 | 12행 |
| 에이전트별 요약 | 3행 |
| 실행시간 측정 가능 행 | 9행 |
| 전체 평균 실행시간 | 약 317.7778ms |
| 전체 중앙값 실행시간 | 250ms |
| 생성 그래프 | 2개 |

중복된 `R03` 기록 한 행이 제거되기 때문에 원본 13행이 정제 후 12행이 된다.

## 7. 생성되는 주요 파일

정상 실행되면 `out` 폴더에 다음 결과가 생성된다.

- `clean_runs.csv`: 정제된 전체 실행 기록
- `summary.json`: 에이전트별 요약 통계
- `quality.json`: 데이터 품질 검사 결과
- `facts.json`: 전체 평균과 중앙값 등의 주요 수치
- `roundtrip_check.json`: 저장 전후 데이터 검증 결과
- `chart_audit.json`: 그래프에 사용한 수치 정보
- `charts/latency_by_agent.png`: 에이전트별 평균 실행시간 그래프
- `charts/latency_hist.png`: 실행시간 분포 그래프

`reports/eda_report.md`는 프로그램이 자동으로 작성하는 결과가 아니다. 분석 결과를 보고 학습자가 직접 작성하는 보고서다.

## 8. 현재 실행되지 않는 이유

현재 확인된 문제는 두 가지다.

### 필수 라이브러리 미설치

현재 선택된 Python 환경에는 `pandas`가 설치되어 있지 않아 테스트가 다음 오류로 중단된다.

```text
ModuleNotFoundError: No module named 'pandas'
```

필요한 라이브러리는 `requirements.txt`에 적혀 있다.

```text
numpy==2.3.5
pandas==2.2.3
matplotlib==3.10.8
```

### `main.py`의 연결 코드 미완성

`main.py`에는 학습자가 직접 완성해야 하는 세 부분이 남아 있다.

- `PIPE_CORE`: 읽기 → 정제 → 집계 → 품질 검사 연결
- `PIPE_FILES`: CSV/JSON 저장 → 다시 읽기 → 왕복 검증
- `PIPE_CHARTS`: 막대그래프와 히스토그램 생성

각 위치에는 의도적으로 `NotImplementedError`가 들어 있다. 따라서 라이브러리를 설치하더라도 이 세 부분을 구현하기 전에는 프로그램이 끝까지 실행되지 않는다.

## 9. 내가 이해한 핵심

- 이 과제는 AI 모델을 직접 만드는 프로젝트가 아니다.
- AI 에이전트의 실행 로그를 분석하는 EDA 프로젝트다.
- EDA는 데이터를 살펴보고 정리하며 특징을 파악하는 탐색적 데이터 분석을 뜻한다.
- 핵심은 준비된 여러 함수를 `main.py`에서 올바른 순서로 연결하는 것이다.
- 잘못된 값을 무조건 0으로 바꾸면 안 된다.
- 실패 기록도 전체 실행 횟수와 성공률 계산에는 필요하다.
- 저장한 결과를 다시 읽어 확인하는 과정도 분석 파이프라인의 일부다.
- 모든 작업이 성공한 경우에만 최종 결과 폴더를 교체하여 기존 결과와 원본을 보호한다.
